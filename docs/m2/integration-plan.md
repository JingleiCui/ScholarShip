# M2 接入实施方案（离线适配已确认并完成）

进度：步骤 1、2 的离线执行及步骤 3 的结果包检查已完成，见[验收报告](offline-report.md)；标准化发布与步骤 4、5 业务链路待[下一增量确认](next-review.md)。

范围：先开发离线适配、持久化成本准入、深解析导入和检索/问答契约。真实模型、文件上传及计费联调保持关闭。公开核验依据见 [供应商核验](provider-verification.md)，账号级未知项没有被标记为通过。

## 实施顺序

1. **离线适配**：独立 MinerU、向量、重排、文本模型边界；从代码配置区读取端点/超时/批量/输出限额，凭据从私有配置读取。使用 httpx MockTransport 和合成响应测试请求契约，禁止测试网络。不会伪装成真实模型成功。
2. **计费与恢复**：外部调用意图、请求摘要和预算预留同事务写入，关闭 SDK 自带重试。提交超时/响应丢失保留 unknown 和预留，先核对回执，不直接新建任务；只对明确可安全重试的失败有限重试，重试也要准入。实际 usage 与账单差异分别记录。
3. **深解析修订**：原件只读，新建 parse；安全下载/解包供应商结果，校验大小、相对路径、页码及版面坐标。短时上传链接不回传浏览器。原始包、标准化块和原件建立血缘，校验通过后发布。PDF 文件页码与供应商页索引转换写入契约测试。
4. **索引发布**：锁定 tokenizer 编码、模型/维度、query/document 参数、分块规则和预处理版本；创建新 profile/世代，完成点数、哈希及 PG 归属回查后原子切换解析/索引指针。失败世代不进入默认问答，保留旧可用组合。
5. **证据问答**：稠密/BM25 各召回 40 → RRF → 首批重排 20 → 最多 8 条证据。账号、项目、profile、版本和世代在召回前限制，并由 PG 二次核对。主张与证据绑定；引文必须匹配原文子串，缺证据保留未知。论文内容按数据处理，不能改变工具权限或成本边界。
6. **界面与验收**：展示深解析/索引进度、支出/预留/未知、证据页码与引用定位。未配置供应商时说明不可用，不自动把 M1 预览包装成深解析结果。

## 预算提案

保留项目 100 元优化目标。建议首批**文本模型＋向量＋重排合计上限 5 元**，该数值是待批准配置，尚未启用；MinerU 单独核实费用后决定，不放进一个未知总价承诺。

离线估算按无免费额度、无缓存、DeepSeek 高峰价格：30 个问题，每题生成输入至多 12,000、输出至多 2,048 Token；文档向量 480,000 Token，问题向量每题 512；重排每题 20 块、每块 900 Token，并计入每个候选重复的 query。结果约 **1.89 元**，另加 50% 余量约 **2.83 元**。这是配置场景推算，非真实测量或账单上限证明。[价格依据](provider-verification.md)

运行 `estimate_m2.py` 可离线重算，[机器结果](../evidence/m2-budget-proposal.json)不包含 OCR、服务器和网络费用。字符数、tiktoken 本地估算不能直接充当供应商精确 Token 数；实际 usage 必须入账，接近限额时停止新准入，未知调用继续占用预留。

**统一准入已补齐**：新增跨账号共享预算池与账务分配表，项目总闸与账号闸同时检查，reviewer 禁止新建计费调用，见[账务设计](billing-design.md)。当前只验证离线执行；真实供应商所有任务及重试仍需在启用前接入，MinerU 费用未知。
