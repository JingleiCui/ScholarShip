# 本地文档处理与中英对应

2026-11-23。新增 `local-document` 解析修订，复用已安装的 Tesseract 和本机 Qwen3.5 9B，不上传 PDF，不读取或恢复已关闭的云端授权。

## 使用

在文献库导入 PDF 后，默认自动执行本地解析/OCR、切片、向量化、索引校验，再排队识图和中文翻译。文献库、阅读页及“与 AI 对话”均展示实际处理步骤；离开或刷新页面不会停止后台任务。

1. 索引完成并且本地模型可用后，直接在“与 AI 对话”发送问题；等待期间可以先输入问题。
2. 准备区显示当前页、已写入/总片段数和索引校验状态；翻译与识图单独计数，失败不阻塞已就绪的原文问答。
3. 对照每块英文与中文，未翻译、部分翻译及待人工核对分别显示。修改沿用已有翻译修订界面，原始版本保留。
4. 图内结构在成果页与原文图块中查看，保留原图、节点、连线、不确定项和人工修订。未经审阅的图推断不自动变成可信问答证据。
5. 旧文献缺少索引时，可点“继续自动准备”。此恢复入口只补齐问答准备，不重试历史失败的翻译。未知模型调用结果须先核对，不自动换任务重发。

根目录 `AUTO_DOCUMENT_PREPARATION` 控制默认自动处理和本地索引请求上限；本地默认最多 128 次调用，每批最多 32 个片段，云端额度与策略不变。自动任务固定导入时的模型配置；改模型后需要匹配的新索引。API 的 `auto_prepare=false` 供自行发布解析修订的受控导入使用，网页默认不跳过自动准备。原有解析、译文、索引和失败记录保留。

## 实现与边界

2026-11-24 的正文分段、标题碎片过滤与问答反馈修复见[正文检索与有界反馈](retrieval-quality.md)。新解析采用 `local-regions-ocr-v3`；历史修订保持可读。

- 页面级路由：根据可提取文字数量和缺失字形比例决定文本层或 OCR，不是整本文档只能选一种。
- 渲染：PDFium 逐页渲染，限制像素，及时释放页面与位图；处理只在 Worker 中顺序执行。
- OCR：Tesseract LSTM TSV 返回词框和置信度，按页面尺寸换算坐标。当前宿主机安装英文语言包；其他语言需先安装对应 traineddata。置信度不是语义准确率。
- 版面：依据空白进行递归分区，列优先并处理跨栏区域间的水平分割；按坐标形成行与段落。PDF 线框表格提取单元格并保留 HTML。阅读顺序和表格结构仍标为未审阅。
- 图像：提取内嵌图片；组合相接的 PDF 矢量线条；对扫描页面遮去已识别文字，再寻找非文字墨迹连通区域。区域保留 PNG 与坐标，属于候选，不保证找全所有图。
- 识图：沿用本地 Gateway、固定模型绑定和节点/连线两阶段契约，输出不可变产物，不覆盖 OCR 文本。
- 翻译：按页分为独立任务，使用稳定 block ID 和源字符范围；已有公式/代码字面量保护及成功片段回执复用机制保持不变。来源哈希不匹配的译文不显示；不把部分翻译标成整块完成，不跨解析拼接旧译文。
- 恢复：父任务与每个子任务有持久化状态和幂等身份，重放父任务不会创建相同子任务；未知模型结果保留并暂停，不自动上传云端。

这是参考版面解析分阶段思想的本地实现，不是重新训练或完整复制 MinerU 模型，也不宣称具有同等通用质量。复杂跨栏、无边框/跨页表格、公式语义、特殊裁剪页面和图连线仍需核对；不把模型返回合法 JSON 当作内容验收。

## 配置与部署

修改根目录 `model_config.py` 顶部 `LOCAL_DOCUMENT_POLICY`，新任务冻结配置，旧任务保留旧配置。可编辑 OCR 语言、DPI、超时、最大页数、像素、任务数与命令路径。图片总字节数另有引擎预算，可在该字典用 `max_asset_bytes` 覆盖。

本地安装 Tesseract 后，用 `tesseract --list-langs` 检查语言；缺失依赖会明确失败，不会隐式下载模型。容器构建文件已加入英文 Tesseract，但本次没有重建或宣称验收容器内本地模型连接。

旧模型配置中的 parser 服务槽位与这里的进程内本地解析是不同入口；这个流程直接执行本地引擎，模型部分只通过本地 chat / translation Gateway，不调用 MinerU 云端 parser。

## 验证

- `backend/tests/test_document_pipeline.py`：真实本地 OCR、双栏顺序、矢量图提取、来源保存、缓存复用、部分译文与本地子任务调度。
- `.venv/bin/python validate.py`：默认离线回归、构建及安全检查。
- `.venv/bin/python -m pytest -q backend/tests/document_pipeline_acceptance.py`：显式真实本地验收，需先停止本项目普通应用；测试使用唯一临时数据库、专用队列与自建 PDF，再启动真实 HTTP/Worker。结束后运行 `dev.py` 恢复日常应用，不修改原账户密码。
- `verify_document_pipeline.py`：已登录测试账号的运行入口，配置在顶部。普通应用账号密码与初始化值不同的情况下，不重置密码；使用隔离验收或通过私有环境变量提供已有测试账号凭据。

本次真实验收对双栏文本与扫描样例分别完成 OCR/文本、识图、翻译及来源对应；并完成本地建索引、中文问题检索英文原文与引用定位。新增云端模型调用 0。桌面与 390px 页面检查无横向溢出。这里只证明自建样例链路，不代表所有论文、公式或图语义已经正确。

机器记录保存在忽略目录 `var/reports/document-pipeline-real.json`、`document-ui.json`，截图和模型回执不进入 Git。

## 解析之后的论文对话

阅读页在文献选择框旁提供“与 AI 对话”入口，未建索引时显示“建立索引并开始对话”。对话区始终展示输入框；索引未就绪时说明准备步骤并提供建索引按钮。解析面板放在“阅读与解析”标签内，避免占据对话页面。

问答按用户与助手消息连续展示，保留真实任务进度、失败信息、回答来源和原文引用。追问提交上一条成功问答的任务身份，由后端沿用已冻结的来源范围；新对话清空上下文但保留历史。历史按文献范围和执行模式分组，刷新可恢复当前会话。界面展示任务步骤，不伪装成逐字流式生成。

`scripts/check_chat_ui.mjs` 由显式本地验收运行：验证真实问题、同一会话追问、刷新恢复、原文引用、新建对话与手机布局。记录保存在忽略目录 `var/reports/chat-ui.json`。测试使用自建资料与隔离数据库，不将局部样例结果当作通用科学问答准确率。

最新默认回归：266 项后端测试通过，其中包含 11 项本地文档与自动准备专项测试、5 项检索质量与反馈专项测试；16 项前端测试、构建、Ruff、依赖健康与敏感信息扫描通过。显式真实本地端到端验收验证了上传自动建索引、进度展示、中文提问、追问、刷新恢复与引用定位，新增云端调用为 0。

还对普通“论文研究空间”中此前无文本层而失败的 15 页扫描 PDF 完成实际本地 OCR：15 页覆盖、无空文本页、508 个内容块、10 个待审阅图像区域；第 7 页可定位 `8 NVIDIA P100 GPUs` 所在段落。只新增本地解析修订，原件、历史修订、原失败记录和旧索引保留，没有自动对整篇追加翻译或图内模型请求。普通服务已恢复。
