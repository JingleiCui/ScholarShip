# 可插拔模型接入与流程重构

2026-11-14，按用户要求整理问题并实施；保留已确认的 FastAPI、LangGraph、PostgreSQL 与 Qdrant 基线。本次仅重构和离线验证，不增加云端额度、不上传真实文件。

## 已发现的问题

1. ProviderClient 同时处理厂商判断、协议、网络、响应和证据校验，增加模型会影响多个文件。
2. 能力与厂商混在一起：Gemma 生成文本，不能作为向量或重排模型。
3. 网络、账号、模型能力、业务结果缺乏分层诊断。公开接口可达不等于推理可用；连接成功也不能保证下一次调用成功。
4. 历次一次性联调脚本重复，授权续接越来越复杂；必须合并，历史 unknown 与计数不可重置。
5. 向量构建已支持原生维度，但业务查询仍偏向旧的合成 profile；需要覆盖完整的同一 profile 构建、检索、重排、证据问答与恢复。
6. 配置文件被重复执行；缺少统一的资源生命周期、能力预检和标准错误信息。

## 目标结构

| 层 | 职责 | 不承担 |
|---|---|---|
| 配置目录与能力注册表 | 提供商、命名模型、角色、批准端点、Key 名称及参数策略 | 不请求模型、不保存 Key 值 |
| 协议适配器 | OpenAI 兼容聊天/向量、Ollama、OpenRouter 重排；统一请求与响应 | 不做预算或任务恢复 |
| 传输层 | 超时、显式代理、TLS、响应大小、脱敏错误分类 | 不决定业务模型、不自动换付费型号 |
| 执行层 | 快照、调用幂等、预算/审批、unknown、用量与回执 | 不解析厂商响应结构 |
| 业务流程 | 解析产物→索引→问题向量→混合检索→重排→证据校验→持久化 | 不包含厂商分支或任意 HTTP |

添加同协议接口：在 model_config.py 添加提供商端点、Key 环境变量名、协议与能力，再增加命名模型并选择配置组。已有协议不修改业务流程。新协议通过注册独立适配器实现。前端只保存已命名选项。

模型输出统一校验：空内容、工具调用、截断、坏 JSON、错型号、异常维度或引文失败都不能发布回答。4096 维实测只作为观察结果，不覆盖旧 1024 维活动索引；切换向量 profile 后先重建、校验，再切活动指针。

## 恢复与效率

- 配置按文件版本缓存，编辑后自动失效；不缓存或输出密钥值。
- 网络连接与客户端使用上下文管理，复用会话，避免额外 HTTP 探针；实际推理不自动重试。只读网络诊断是独立工具。
- 成功调用复用回执；unknown 停止流程并保留占额。429 保存 Retry-After，仅提示等待，不能静默重发。
- 统一联调入口，固定一份清单和累计额度；无审批状态时默认只读。真实发送仍受 PG 原子计数控制。
- 以数据库与向量库集成测试证明流程衔接，以合成协议测试证明可替换性，分别报告真实云端可用性。
