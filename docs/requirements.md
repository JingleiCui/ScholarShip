## 3. 产品原则

1. 事实结论必须关联证据；文献真实存在与文献支持论断分别核验。只有摘要时明确标注证据范围。
2. 每个原文锚点指向明确论文版本和解析版本；重新解析后不静默改写历史引用。
3. 用户决定论文版本保留策略；默认不自动删除或覆盖原文件。
4. 不能保证绝对零幻觉。通过可追溯证据、拒答、冲突展示和人工检查降低错误，并报告实测结果。
5. “未检索到后续解决证据”不等于证明问题未解决；展示检索范围、时间与覆盖限制。
6. 引用价值和局域中心性是可解释辅助指标；普通提及和相反证据均可有科研价值，不因模型判断而物理删除。
7. 公网演示必须能实际发起任务；预计算数据只能作为有标签的演示数据，不能冒充实时结果。
8. 各模块完整覆盖；进阶质量按验收与剩余时间提升，未通过项如实列出。

## 4. 提交物

- GitHub/Gitee 可评审源码、真实 Git 历史、清晰注释与第三方来源说明。
- README：项目、架构、安装运行、参赛者信息。
- 依赖锁定、环境变量模板及可复现部署说明；密钥不进入公开仓库。
- 5–8 分钟、至少 1080p、普通话讲解的 MP4 演示视频。
- 不超过 30 页的 PDF 技术文档，覆盖需求、架构、AI 方案、实现、测试部署、创新与限制。
- 公网演示地址；需要登录时提供评审测试账号，评审期间保持可用。
- 技术文档披露 AI 辅助开发贡献、核心 Prompt 策略和开源复用来源。
